1. Introduction

Web-Based Slide Deck Systems

  • Slide deck created with HTML, CSS, and JavaScript:
    • Distributed as URL.
    • Presented in a web browser.
  • Multimedia and interactive slide content.
  • Authors use standard web development tools.

2. Modern Web Technologies

Living HTML and the DOM

  • HTML is maintained as a Living Standard.
  • HTML structure and semantics.
  • Semantic elements for structure and accessibility: <section>, <figure>, <table>.
  • Native media elements: <video>, <audio>, <picture>.
  • DOM as hierarchical object tree.
  • JavaScript-based DOM access and manipulation.

Modern CSS

  • Flexbox and Grid for flexible layouts.
  • Custom properties (variables) for configuration and themes.
  • Media and container queries for responsiveness.
  • :has() for relational styling.
  • light-dark() and color-mix() for modern colour systems.

JavaScript

  • Dynamically typed programming language.
  • Variable types are determined at runtime.
  • Type errors may only appear during execution.
  • Runs directly in browsers and Node.js.

JavaScript executes the incorrect function call, but produces an unexpected result. 

function addSlideNumbers(
    current,
    total
) {
    return current + " / " + total;
}

const result = addSlideNumbers(
    "one",
    10
);

console.log(result);
// "one / 10"

TypeScript

  • JavaScript extended with static typing.
  • Variable and parameter types are explicitly defined.
  • Type errors are detected during development.
  • Transpiles to standard JavaScript.

TypeScript detects the incorrect argument before the program is executed. 

function addSlideNumbers(
    current: number,
    total: number
): string {
    return `${current} / ${total}`;
}

const result = addSlideNumbers(
    "one",
    10
);
// Error: string is not assignable to parameter of type number

Responsive Web Design

  • Single code base, served under single URL.
  • Website or app adapts to devices and available space.
  • Scalable typography and spacing through relative units.
  • Flexible images.
  • Media queries for viewport and output characteristics.
  • Container queries for reusable responsive components.

3. Web-Based Slide Decks

Four Categories

  1. Text-Based: Markdown syntax. Simple, lightweight, fast to create and change.
  2. JavaScript-Based: HTML, JavaScript, and CSS. Interactive, powerful styling, advanced animations.
  3. Hosted: Online tools. Easy collaboration and sharing.
  4. Responsive: Responsive slide decks, adapting to wide variety of devices and screen sizes.

4. Rslidy v1

Rslidy v1: Architecture

  • Single HTML document for complete slide deck.
  • <section> for each slide.
  • JavaScript-based slide viewer.
  • Components for navigation, settings, printing, and media.
  • Shared state through the central Rslidy runtime.

Rslidy v1: Responsive Design

  • CSS controls slide layout, transitions, themes, and print output.
  • Separate screen and print media contexts.
  • Relative units for scalable typography and spacing.
  • The slide area adapts to the browser viewport.
  • Responsive columns, toolbar controls, and panels.

Rslidy v1: Navigation and Interaction

  • Keyboard shortcuts and toolbar controls.
  • Mouse, touch, and margin-based navigation.
  • Slide overview and table of contents.
  • Incremental content advancement.
  • Tilt and tip gestures on supported mobile devices.

5. Rslidy v2

Rslidy v2: System Modernisation

  • Package Management: NPM → PNPM; less disk usage; faster installs; stricter dependencies.
  • TypeScript: Updated compiler, Node.js type definitions, generated declaration files.
  • Build Pipeline: Extended Gulp workflow.
  • Module Formats: ESM, CommonJS, and UMD distributions.
  • Optimisation: Minified JavaScript and CSS; Gzip and Brotli compression.
  • Asset Generation: SVG icons → TypeScript definitions; automatic theme and asset copying.
  • Development Workflow: BrowserSync; file watching; automatic rebuild and browser reload.

Rslidy v2: Redesigned Print Settings Panel

  • Four logical groups of settings.
  • Individual slides and inclusive slide ranges.
  • CSS print styles dynamically generated.
  • @page rules from paper format and orientation.
  • Print Sizing: Actual Size, Fit to Page Width, or Custom Zoom.
  • Persistent print settings through local storage.

Rslidy v2: Responsive Tables

  • Container-based responsive breakpoint.
  • Identical table definition for both layouts.

Rslidy v2: Dynamic Print CSS Generation

  1. Read selected print settings.
  2. Validate custom slide ranges.
  3. Mark slides for output.
  4. Generate page, scaling, frame, and visibility rules.
  5. Replace generated stylesheet.
  6. Open browser print preview.

Rslidy v2: Interactive Sorting

  • First activation: sorts in ascending order.
  • Second activation: sorts in descending order.
  • Third activation: restores original row order.
  • Normalisation of text, numeric, and date-like values.
  • Independent sorting state per table.
  • Shared state for desktop and mobile controls.
